# FrameGenX quality assessment — 2026-10-13

## Scope and test environment

This assessment covered the repository's React/Vite UI, FastAPI endpoints,
SQLite run tracking, Milvus Lite retrieval, the GPU generation/verification
pipeline, packaging configuration, and documented workflows. The local test
environment was Windows, Python 3.14.6, and an RTX 3050 Laptop GPU with 6GB
VRAM. `pip check` found no broken installed requirements.

The application's default flow is: prompt -> intent contract -> local caption
retrieval -> plan -> SDXL-Turbo generation -> GroundingDINO count/spatial
verification plus CLIP and external vision QA -> reflection -> optional image
refinement -> SQLite/artifact persistence. The default `hard_only` acceptance
rule checks counts and spatial relations. CLIP and vision QA are diagnostic.

## Verified behavior

- A full local run for `A red cat sitting on a blue chair` completed generation,
  verification, refinement, and database logging in 245.3 seconds. It produced
  a nonblank 512x512 image in `runs/0d732f9f-74b6-4a15-b874-e3ea6b4f1a15/`.
  GroundingDINO found one cat and one chair; the hard checks passed. CLIP norm
  was 0.6968. The external vision providers timed out, so attributes were not
  verified in that run. This historical artifact predates the unavailable VQA
  representation change below.
- In-process FastAPI calls returned a cached job for that run, its image and
  attempt artifacts, and a successful history/stats response. `/stats` returned
  zero attributable benchmark rows after provenance filtering.
- Pagination bounds, malformed/missing artifact IDs, unsupported contract
  submission, busy GPU behavior, cache image selection, and local CORS policy
  are covered by API tests.
- React lint, production build, and saved-run verdict tests pass. This confirms
  static/code behavior, not human-visible rendering.

## Defects repaired

| Area | Reproducible failure | Change |
| --- | --- | --- |
| Acceptance evidence | A saved run with rejected decisions appeared accepted in the demo. | UI verdict is derived from recorded decisions; demo points to an accepted saved run. |
| Prompt integrity | Retrieved captions and LLM rewrites could replace/contaminate the user's prompt. | Plan retains the original prompt plus corrective edits; captions remain inspection evidence. |
| Hard gate | `hard_only` could accept a high-reward run with hard failures. | Hard failures now block acceptance. |
| Generation | Compel produced meta-device embeddings under 6GB sequential offload. | Use Diffusers' own prompt encoder; a real GPU image test passes. |
| Retrieval | Milvus clients were dropped without closing their connections. | Explicit close on unload and cleanup after retrieval/memory use. The integrated run passed, though gRPC still logged a keepalive GOAWAY. |
| Windows console | Logging a non-ASCII rewritten query raised a CP1252 encoding error and discarded the successful rewrite. | Log the rewrite length; regression test covers a strict CP1252 stream. |
| Vision QA evidence | Provider timeout was recorded as score 0, falsely implying an observed failure and a valid composite reward. | New artifacts record `vqa_status: unavailable`, null VQA/reward, and unavailable per-question answers. UI also recognizes legacy all-error artifacts and describes the unverified attributes. |
| Benchmark provenance | Ordinary historical `full` runs could appear in CSR and prevent benchmark resume. | Explicit benchmark flag and seed are persisted; legacy ambiguous rows are excluded. |
| API / security | Invalid pagination was unbounded, missing artifact IDs returned success, contract input was silently ignored, cached sync response could select a mask, and default network/CORS exposure was broad. | Validate inputs/IDs, reject unsupported contract input, select actual generated images, bind native/Docker host exposure to loopback, and restrict default CORS. |
| Interaction states | Rapid duplicate submissions, refresh during a job, and fetch failures had misleading or silent states. | UI submission lock, persisted job ID/poll resume, retry/error states, and decision-aware attempt display. |
| Dependency manifest | Duplicate and missing runtime dependencies made a clean install unreliable. | Align runtime manifests with the tested local versions and remove unused Compel. |
| Secret staging | `.env` had been staged in the working tree. | Removed it from the index, kept the local file, and added ignore rules. It was not present in `HEAD`. |

## Remaining limits and risks

- **Browser testing blocked.** The browser automation security policy rejected
  access to the local application URL and explicitly disallowed an alternate
  browser/Playwright/CDP workaround. No visual, mobile, keyboard, WCAG, or
  cross-browser pass is claimed; no screenshots were captured.
- **External vision QA unavailable in the integrated run.** Count/spatial hard
  checks passed, but color and other attribute probes did not run to completion.
  The default acceptance mode intentionally does not gate on VQA, so “hard
  checks passed” must not be read as full contract satisfaction.
- **No new benchmark claim.** Existing rows lacked trustworthy benchmark
  provenance. The dashboard now shows no attributable benchmark rows; a fresh
  controlled benchmark is needed for an updated CSR comparison.
- **Public deployment needs an auth design.** The API and run artifacts have no
  user authentication or tenant isolation. Loopback defaults limit local
  exposure; changing the bind address or publishing the service changes the
  threat model.
- **External prompt routing needs a clear user control.** Intent extraction
  and vision QA call configured external AI providers. Retrieval may send the
  prompt to DuckDuckGo when local captions fail grading. The prompt form now
  discloses this routing, but there is no per-run network opt-in.
- **Container unverified.** Docker Desktop's Linux daemon was unavailable, so
  the image and Compose startup were not built or tested in this assessment.
- **No CI workflow was found.** The local pytest, lint, and build checks are
  not currently enforced by a repository CI pipeline.
- **Historical design documents need a provenance pass.** Some older research
  pages still describe BLIP VQA, ControlNet conditioning, or reward-gated
  default acceptance. The README and this report describe the current code;
  those older pages should be labeled historical or updated before reuse.
- **Milvus transport warning remains.** A `too_many_pings` GOAWAY appeared
  during the passing full run. Repeated runs and recovery after a Milvus Lite
  restart still need observation.
- **Workspace cleanup was policy-blocked.** Automatic approval review rejected
  recursive deletion of the `.pytest_tmp_qa*` directories created for this
  assessment. Those temporary test directories remain in the workspace.
